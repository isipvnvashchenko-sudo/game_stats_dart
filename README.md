# Система управления зоомагазином (Pet Shop CLI)

Консольное приложение на Dart для управления данными зоомагазина. Проект реализует CRUD-операции для основных сущностей, включает проверки вводимых данных и покрыт Unit-тестами.

---

## 1. Предметная область и сущности
**Предметная область:** Учет товаров и продаж в зоомагазине. Система позволяет управлять ассортиментом, вести базу клиентов и оформлять заказы. 

В проекте создано 4 основные сущности:
* **Category** (Категория товаров, например: "Собаки", "Кошки").
* **Product** (Конкретный товар с указанием цены и остатка на складе).
* **Customer** (Клиент магазина).
* **Order** (Заказ клиента).

---

## 2. Реализованный функционал (по требованиям задания)

* **CRUD-операции:** Для каждой из сущностей (категории, товары, клиенты, заказы) в слое репозиториев реализован полный набор базовых операций: добавление (Create), чтение (Read), обновление (Update) и удаление (Delete).
* **Связи между сущностями:** Сущности логически связаны между собой. Например:
  * Каждый товар (`Product`) имеет поле `categoryId`, связывающее его с конкретной категорией.
  * Каждый заказ (`Order`) привязан к конкретному клиенту через `customerId` и содержит перечень идентификаторов купленных товаров.
* **Показать всё из БД:** В консольном меню (CLI) реализован отдельный пункт для вывода всех существующих записей из базы (список всех товаров, всех категорий или клиентов) для удобной проверки текущего состояния данных.

---

## 3. Структура проекта и слои

Проект разделен на слои для удобства масштабирования и соблюдения принципов чистой архитектуры:

* **Слой CLI (`cli/`):** Отвечает исключительно за взаимодействие с пользователем (ввод с клавиатуры, вывод меню). Это позволяет легко заменить консольный интерфейс на графический без изменения логики.
* **Слой Models (`domain/data/models/`):** Содержит классы сущностей. Это "сердце" приложения, описывающее наши объекты.
* **Слой Repositories (`domain/data/repositories/`):** Изолирует логику хранения данных. Здесь реализованы все CRUD-операции.
* **Слой Validators (`domain/data/models/validators/`):** Вынесен в отдельные функции для переиспользуемости. Проверяет данные до того, как они попадут в бизнес-логику.
```text
lib/
└── src/
    ├── cli/                  # Слой представления (User Interface)
    │   └── input_helper.dart
    ├── domain/               
    │   └── data/
    │       ├── models/       # Бизнес-сущности (Domain Layer)
    │       │   ├── category.dart
    │       │   ├── product.dart
    │       │   ├── customer.dart
    │       │   ├── order.dart
    │       │   └── validators/
    │       │       ├── text_validator.dart
    │       │       └── number_validator.dart
    │       └── repositories/ # Слой доступа к данным (Data Layer)
    │           ├── category_repository.dart
    │           └── product_repository.dart
test/                         # Слой тестирования
    ├── validation_test.dart
    ├── domain_test.dart
    └── data_test.dart
```

## 4. Реализованные валидации

Для защиты системы от некорректного ввода реализовано 2 требуемых типа валидации:
1. **Обязательное текстовое поле:** Функция `isValidText` проверяет, что введенная строка не является пустой и не состоит только из пробелов (`text.trim().isNotEmpty`). Применяется для названий товаров и имен клиентов.
2. **Числовое поле (больше 0):** Функция `isPositiveNumber` проверяет, что введенное число строго больше нуля (`value > 0`). Применяется для цен товаров (`price`) и количества на складе (`stock`).
